# 三路管线规格 · 从需求到总结论

> 这是本 skill 的核心。SKILL.md 是概览，**这一份是可照做的执行规格**。
> 每一步都写了「输入 / 动作 / 输出 / 质量门」。**质量门不过，不许进下一步。**

---

## 阶段总览

```
用户需求
  │
  ├─ 阶段1  判断三大类 + 解析参数                  [主窗口]
  │           ↓ social / science / ai —— 只选一个
  │
  ├─ 阶段2  三路并行（都限定在该类内）──────────────┐
  │            ├─ 子代理A 社会面                    │
  │            ├─ 子代理B 权威面                    │  同时
  │            └─ 主窗口   热度榜（利用等待时间）    │
  │          三份原始池 ◄──────────────────────────┘
  │
  ├─ 阶段3  验证：三要素 + 合并 + 交叉核对          [主窗口]
  ├─ 阶段4  精华萃取                               [主窗口]
  ├─ 阶段5  回看（对抗 lost-in-the-middle）        [主窗口]
  ├─ 阶段6  主体结论 + 横向结论                    [主窗口]
  ├─ 阶段7  对照校验                               [主窗口]
  └─ 阶段8  总结论 → **只输出到聊天，不落文件**
```

**只有阶段 2 用子代理。** 其余全部在主窗口做 —— 子代理没有全局视野、看不到彼此的中间过程，
而验证和回看**恰恰依赖全局视野**。

## 阶段 1 · 判断三大类 + 解析参数

### 第一步是分类，不是解析

用户的话进来，**先判断它属于三大类里的哪一类**。这一步决定后面所有源怎么路由。

| 类 | `--domain` | 覆盖 | 源数 |
|---|---|---|---|
| **社会** | `social` | 热点新闻、公共事件、政策、人文 | 7 |
| **科学进步** | `science` | 生物医学、Nature/Science 等大刊、科学进展 | 19 |
| **AI** | `ai` | 模型、方法、基准、AI 产业 | 13 |

（一个源可以同时属于多类，所以三个数加起来大于总源数。）

**判断规则**：

- 提到具体学科、期刊、疾病、材料、生物 → **science**
- 提到模型、算法、训练、benchmark、某家 AI 公司 → **ai**
- 提到事件、政策、事故、社会现象、公众讨论 → **social**
- **判断不了就【问用户】，不要猜。** 判完在输出开头声明分成了哪一类。

### 跨类冲突：优先级规则

**规则：显式 `--domain` 永远优先。** request 文本命中的类只作**补充**，不覆盖显式选择。

实测问题：`--request "AI安全"` + `--domain science` 时**没有定义谁赢** ——
代码里 `--domain` 事实上赢（它决定源），但 `request_type` 仍按 request 文本判，
两者不一致。现在 `--domain` 同时赢源选择与分类判定。

**视角规则**（需求跨两类时，按**用户问的角度**定，不按话题定）：

| 需求 | 分到 | 为什么 |
|---|---|---|
| AI 对就业的影响 | `social` | 问的是社会影响，不是技术 |
| 某模型的能力边界 | `ai` | 问的是技术 |
| 某篇论文的临床意义 | `science` | 问的是科学结论 |
| 某论文成果的产业落地 | `social` 或 `ai`（看落地方向） | 问的是应用 |
| 某公司发布会的技术细节 | `ai` | 问的是技术 |
| 某公司发布会的市场反应 | `social` | 问的是市场 |

**判据一句话**：**问的是「它是什么」→ 技术类；问的是「它影响谁」→ 社会类。**

**★判不了就问用户。** 猜错会污染后面全部阶段，而且**没有任何下游环节能发现**
（阶段 3 只验内容真不真，不验分类对不对）。

**置信度**：脚本会写 `relevance.classification.confidence`。
低于 0.7 时输出 `classification_warning` —— **看到这个警告必须人工确认分类**。


### 然后补齐参数

| 参数 | 默认值 |
|---|---|
| **时间窗** | 近 3 天（「今天」= 24h，「本周」= 7 天） |
| **条数** | **动态 3–8 条**（`science` 可到 8）。合格不足就少放，**最低 0 条，禁止凑数** |
| **语言** | 中文输出，标题保留原文 |
| **特别关注** | 用户点名的对象，可空 |

**时间窗规则**：检索词里带年份月份（`AI 2026年10月`、`October 2026`），
拿到结果**再用条目自带日期筛**。期刊按**在线发表日期**算 —— 已实测：
Crossref 按「出版日期」排会漏掉大刊全部新文章（它们的期号日期滞后数月），
脚本已改用 `published-online`。

**输出**：参数卡（分类 + 时间窗 + 条数 + 关注点）

## 阶段 2 · 三路并行

> **技术前提**：只有主窗口能开子代理，子代理不能再开子代理。
> 三路**必须并行发起**（同一条消息里），否则等待时间就浪费了。

**每一路都带上 `--domain <阶段1判断的类>`。**

### ⚠️ 两个必加的参数（省一半读入量）

```bash
--compact           # 同时写 <out>_compact.json
--out "$env:TEMP\..."   # 必须写文件，Windows 控制台是 GBK
```

**子代理和主窗口读的是 `_compact.json`，不是全量那份。**

| 文件 | 体积（实测一次三路运行） | 给谁读 |
|---|---|---|
| `<out>.json` | **320 KB** | 别读。只在需要回查被截断的摘要时用 |
| `<out>_compact.json` | **158 KB** | **✅ 读这份** |

精简视图去掉了**能从其他字段推导出来的**键（`weights` 是 1.7 KB 常量每条运行重复一遍、`published_raw`、`also_titles`、`also_event_ids`），并把超长摘要截到 600 字并标 `summary_cut`（值为原文全长）。

**判断需要的字段一个没删**：分数、分区、证据类型、`event_id`、来源、独立转载、风险标记、审计理由、`sources_report`、`source_funnel`、`degraded_streams` 全部保留。

> **为什么要标 `summary_cut`**：不标的话下游会以为拿到的是全文。
> **省 token 不能以「让人误以为看到了全文」为代价** —— 那比多读 160 KB 危险。

### 逐源耗时（新增，用来看哪一路被拖住）

脚本现在每次运行都打印：

```
耗时 : 合计 6.5s | 最慢 ithome 1.95s | ≥5s 的源: reddit-ml=12.58s
```

每个源的秒数也写进 `sources_report[].seconds`。

> ⚠️ **`合计` 是「各源耗时之和」，不是并行墙钟。**
> `fetch_feeds.py` **纯串行**（`for key in keys:` 单循环，无 Thread / Pool / asyncio）。
> 所以「合计」≈ 墙钟 —— 它就是墙钟的分解。
> **不要把它当并行加速后的数字。**（我一度声称「三路并行把墙钟从 37s 降到 20s」，
> 那是错的。三路之间并行是**子代理调度**带来的，与脚本内部无关。）

**实测全部 30 个源各跑 3 次的最大值**：

| 源 | 最大 | 中位 | 说明 |
|---|---|---|---|
| `arxiv-ai` | **11.29s** | 9.43s | 合法慢：4 个分类各一次请求 + `ARXIV_GAP=3s` 礼貌间隔 |
| `reddit-ml` | 7.35s | 6.89s | 全在等退避（429），0 条 |
| 其余 28 个 | **均 < 4.8s** | | |

> **两条互为反向的教训，都要记住：**
>
> **① 最慢的源需要的是【更大的】超时，不是更小的。** `arxiv-ai` 在 4 分类下耗时
> ≈ 9.4 + 3×3 = 18.4s，全局 `TIMEOUT=25s` 余量很小，网络稍慢就会
> **截断合法的分类数据**。已给它单独设 **40s**。
>
> **② 单次测量会骗人，不要据此压超时。** `ithome` 第一次测出 **14.25s**，
> 复测 4 次是 `1.05 / 2.08 / 2.17 / 1.99`（中位 **1.99s**）—— 那个 14s 是瞬时抖动。
> 按单次测量给它压低超时，会真的造成丢数据。
>
> `reddit-ml` **故意不设超时**：它现在稳定 429，但那是限流不是响应时间，
> 按限流耗时设超时会反过来切断它恢复后的正常响应。**没有可靠数字就不设。**

### ⚠️ `seconds` 会因 HTTP 缓存失真

`_get()` 有进程内缓存，缓存键是 `(url, ua, timeout)`。
`hn-frontpage` 与 `hn-top` 这三个值**完全相同**，所以同进程内后抓的那个记 **0.0s**
（实测；单独抓是 0.58s）。

**`seconds` 是「抓取或命中缓存」的延迟，不是该源的网络成本。** 要测真实成本就单源单独跑。


### 退避已缩短

`RETRY_WAITS` 从 `(4.0, 12.0)` 改成 `(2.0, 4.0)`。
理由：429 是"这个源此刻不给数据"，多等 12 秒不会让它给 —— 实测 `reddit-ml` 单源耗 **17.06s，其中 16s 纯 sleep**。


### 路 A · 子代理「社会面」

**负责**：热度、风向、爆料、传言、社区反应、行业八卦。
**它的活**：快。抓的是**「大家在说什么」**，不是「事实是什么」。

```bash
python scripts/fetch_feeds.py --domain <DOM> --class social --days <N> --max-per-source 15 --compact --out "$env:TEMP\radar_social.json"
```

**子代理提示词模板**（照抄，替换 `<DOM>` / `<主题>` / `<天数>`）：

> 你是情报管线的**社会面**采集员。分类：`<DOM>`。主题：`<主题>`。时间窗：近 `<天数>` 天。
>
> 执行：
> 1. 跑 `python scripts/fetch_feeds.py --domain <DOM> --class social --days <天数> --max-per-source 15 --compact --out "$env:TEMP\radar_social.json"`，
>    然后读该 JSON（不要读原文页，除非某条必须核对）。
> 2. 若不足以覆盖主题，用 `web_search` 补 2–4 次查询，**检索词带年份月份**。
> 3. 从结果里挑出**最多 12 条**，按下面契约返回。
>
> **产出契约**（严格照此，缺字段视为不合格）：
> ```json
> {"stream":"social","domain":"<DOM>","scanned":["<实际抓到的源>"],"failed":["<失败的源及原因>"],
>  "items":[{"claim":"<一句话事实陈述>","source":"<媒体名>","url":"<可点击链接>",
>            "date":"<YYYY-MM-DD 或 未标>","heat":"<热度信号，可空>",
>            "elements":{"new":"yes|no|partial","truth":"yes|no|partial","comm":"yes|no|partial"},
>            "signal_words":["<修饰词/感叹号，原样保留>"],
>            "opinion_discarded":"<丢掉了什么观点，一句话>",
>            "kept_detail":"<保留的关键过程/数字/限定>",
>            "confidence":"high|medium|low",
>            "why_it_matters":"<改变谁做什么>"}]}
> ```
>
> **要交三要素判断**（每条都要给）：
> - `new` **新**：此前有没有公开过？还是旧闻重发 / 别处已报？
> - `truth` **真实**：能不能回溯到一手来源、数据、原文？
> - `comm` **传播报道**：有没有被实际报道过？（只有一条贴文不算）
>
> **社会面特有的动作 —— 事实与观点是混在一起的，你要做二次分类**：
> 把每条拆成「事实部分」和「观点部分」，**只把事实部分放进 `claim`**，
> 观点写进 `opinion_discarded`。这条源的价值就在这个拆分上 ——
> 不拆，社会面就只是一堆情绪。
>
> **萃取规则见下方「通用萃取规则」** —— 两个子代理都要遵守。
>
> **硬约束**：
> - 每条必须有 URL。没有 URL 的**不要返回**。
> - 热度高不等于真实，不确定的 `confidence` 如实标 `low`。
> - 同一条新闻的多家转载**不算多条**。
> - `scanned` / `failed` **必须如实填写**（下游判断覆盖率要用）。
> - **不写结论、不写建议** —— 只交素材，判断由主窗口做。

### 路 B · 子代理「权威面」

**负责**：期刊论文、官方公告、机构发布、可核查事实。
**它的活**：慢但准。抓的是**「什么是真的」**。

```bash
python scripts/fetch_feeds.py --domain <DOM> --class authority --days <N> --max-per-source 15 --compact --out "$env:TEMP\radar_auth.json"
```

**子代理提示词模板**：

> 你是情报管线的**权威面**采集员。分类：`<DOM>`。主题：`<主题>`。时间窗：近 `<天数>` 天。
>
> 执行：
> 1. 跑 `python scripts/fetch_feeds.py --domain <DOM> --class authority --days <天数> --max-per-source 15 --compact --out "$env:TEMP\radar_auth.json"`，然后读该 JSON。
> 2. 补充：`web_search` 找该领域官方公告 / 机构发布（检索词带年份月份）。
> 3. 对**确定要进核心区的 1–3 条**用 `web_fetch` 读正文，核对数字与结论。
>
> **产出契约**（与路 A 同构，`stream` 改为 `"authority"`，多一个 `evidence_type`）：
> ```json
> {"stream":"authority","domain":"<DOM>","scanned":[...],"failed":[...],
>  "items":[{"claim":"...","source":"...","url":"...","date":"...",
>            "elements":{"new":"...","truth":"...","comm":"..."},
>            "evidence_type":"peer-reviewed|preprint|official|dataset|secondary",
>            "signal_words":[...],"opinion_discarded":"...","kept_detail":"...",
>            "limits":"<原文自己承认的局限，没有就写 无>",
>            "confidence":"...","why_it_matters":"..."}]}
> ```
>
> **权威面特有的动作 —— 主动过滤冗余，只留核心事实**：
> - 砍掉：主观情绪、无关八卦、网友感想、夸张修辞、冗长背景铺垫
> - 留下：核心事实、方法、结果、数据、限定条件、作者自认的局限
> - `limits` **要抄原文**，不要自己替作者说「可能」
>
> **萃取规则见下方「通用萃取规则」** —— 两个子代理都要遵守。
>
> **硬约束**：
> - **`evidence_type` 必须如实标**：预印本绝不能写成 `peer-reviewed`。
> - 付费墙只拿到摘要时，在 `limits` 里写「仅凭摘要」。
> - 勘误（`Correction` / `Erratum` / `Retraction`）不要当新发现返回
>   （脚本已过滤一轮，你要再核一遍）。
> - 同样：**不写结论，只交素材**。

> **两个子代理的差别，一句话**：
> 权威面是**过滤冗余**（信息本来就干净，挤掉水分）；
> 社会面是**二次分类**（事实和观点搅在一起，先拆开再取）。

### 路 C · 主窗口「热度榜」

**在子代理跑的时候做，不要等。**

```bash
python scripts/fetch_feeds.py --class trend --max-per-source 15 --compact --out "$env:TEMP\radar_trend.json"
```

（热度榜**不分三大类** —— 它衡量的是全体公众的注意力。）

**为什么这一路必须存在**：

1. 热榜**即刻可用**，而两个子代理要跑几十秒到几分钟 —— 白捡的时间。
2. 它是**独立于两个子代理的第三视角**：告诉你「公众真正在看什么」。
3. 没有它，你无法回答「这件事到底有没有传开」——
   只有权威面你只知道「发生了什么」，只有社会面你只知道「圈内在聊什么」。

**路 C 只有两个用途，别扩大**：

- **校准传播度**：另两路里的某条**在热榜上出现了** → 已破圈，值得往前提。
- **发现遗漏**：热榜上很高但另两路都没抓到 → **必须显式判断**是噪声还是真遗漏。

> ⚠️ **热度 ≠ 价值。** 实测同一时刻：百度热搜是「宋佳集齐三大奖」、
> 头条热榜第 1 是 WTT 乒乓球四强、Google Trends 前 10 **全是人名**。
> 热榜条目**默认一条都不进核心区**，除非能在另两路回溯到一手来源。

## 通用萃取规则（两个子代理都遵守）

### 必须保留 —— 看着像废话，实际是信息密度最高的地方

| 保留项 | 为什么 |
|---|---|
| **详细过程** | 怎么做的，才知道可不可靠 |
| **次要细节** | 常藏着可证伪的关键（样本量、时间、地点、条件） |
| **举例** | 具体案例比概括更可核查 |
| **数字说明** | 唯一的硬证据。含糊量词一律换成数字，或标「未给数」 |
| **机制/原因** | 「为什么」比「是什么」更有价值 |
| **限定条件** | 「在 X 条件下」「仅适用于 Y」—— 砍掉它就变成夸大 |

### 必须屏蔽

| 屏蔽项 | 例子 |
|---|---|
| **主观评论、感受** | 「令人震惊」「我认为」「太失望了」 |
| **额外观点、引用他人看法** | 「专家称」「有网友认为」（除非该观点本身是新闻事实） |
| **修辞：比喻、拟人、夸张** | 「如猛虎下山」「AI 的寒冬来了」 |
| **文学化描述** | 场景渲染、情绪烘托、故事化铺陈 |
| **无关八卦** | 与事实无关的人物、私生活、花边 |
| **纯情绪宣泄** | 感叹、辱骂、讽刺 |

### ⚠️ 但「修饰词」和「感叹号」是例外 —— 不要当噪声丢掉

**形容词、副词、程度词、感叹号要留下并单独标出。** 原因：

> 它们是**偏见检测信号**，不是废话。
> 「**大规模**裁员」和「裁员」是两条不同的事实主张；
> 「**彻底**失败」里的「彻底」是报道者的判断，**必须能被下游看见并质疑**。
> 把它们当噪声洗掉，等于替报道者把偏见藏了起来 —— 这比留着更危险。

所以做法是**两件事都做，不是二选一**：

1. 这些词**进 `signal_words` 字段**（原样保留，供下游质疑）
2. 同时它们**不进 `claim`**（`claim` 只放可核查的事实陈述）

### 输出字段

```json
{"claim":"<只留事实，去掉评价性语言>",
 "signal_words":["大规模","彻底","首次"],
 "opinion_discarded":"<丢掉了什么观点，一句话>",
 "kept_detail":"<保留的关键过程/数字/限定>"}
```

## 阶段 3 · 验证（三要素 + 合并 + 交叉核对）

**输入**：三份 JSON
**动作**：先过三要素，再做交叉核对。**这是最容易走过场的一步，必须逐条留痕。**

### 3a · 三要素检查（每条都要过）

| 要素 | 谁来定 | 判定 | 不过怎么办 |
|---|---|---|---|
| **新** | **模型判断** | 此前公开过吗？旧闻重发？ | 降级到「背景」，不进核心区 |
| **真实** | **脚本算的 `truth_score`** | ≥ 0.6 才算过 | < 0.6 → 存疑区 |
| **传播报道** | **脚本算的 `comm_score`** | ≥ 0.6 才算过 | < 0.6 → 待观察区 |

> ⚠️ **真实与传播必须用脚本算出来的分，不许自己估。**
> 脚本按 `SOURCE_WEIGHT × EVIDENCE_WEIGHT` 和独立来源数计算，**同样的输入永远同一个分数**；
> 模型现场估分则每次不同，0.6 这条闸门就无法审计了。
> 完整规则与依据见 `quality-bar.md` 第〇节。
>
> **`新` 不打权重分** —— 新出现的东西本来就没有转载，用同一把尺子量它会
> 系统性筛掉最新内容。所以 `新` 留给模型判断，写成 `yes / no / partial`。

**三要素全过**才进核心区候选。

> ⚠️ **撤稿拦截（优先级高于一切）**：脚本会读 Crossref 的 `update-to` 记录，
> 凡带**撤稿 / 关注声明 / 更正**的条目，真值分被强制压低（撤稿 → 0.05），
> 并标 `record_alert`。**撤稿的条目无论被多少家转载都不得作为事实依据**，
> 直接放存疑区并写明。
>
> **但要知道这个补救的边界**：它只在**撤稿记录存在**时生效。
> 一项**从未被撤稿、只是没人能复现**的结论（LK-99、OPERA 都是这种），
> 权重给不出任何警告。**防住这类错靠的是 3c 交叉核对和待观察区，不是权重。**

### 3b · 三个分区（不要合成一个分）

脚本已经把每条分好了，直接照用：

| 分区 | 条件 | 怎么处置 |
|---|---|---|
| **核心区** | 真实 ≥ 0.6 **且** 传播 ≥ 0.6 | 进精华萃取 |
| **待观察区** | 真实 ≥ 0.6，传播 < 0.6 | **可核查但还没传开 —— 不是噪声，不要丢** |
| **存疑区** | 传播 ≥ 0.6，真实 < 0.6 | 传得广但不可信，**必须标出来** |
| 丢弃 | 两项都 < 0.6 | 丢 |

**真实与传播不许合成一个分。** 合成就分不出这两种最该被看见的情况：
「很可信但没人报」（可能是重要的冷门发现）和「传得很广但不可信」（可能是谣言）——
**处置完全不同。**

> **核心区可能是空的，这是正常的。** 实测：AI 域 2124 条 → 核心区 1 条；
> science 域 375 条 → 核心区 0 条。
> 根因是两面**反相关** —— 权威面新发的论文天然单源（传播 0.30），
> 而传播广的是低真值源。
>
> **核心区的语义是「已交叉验证」，不是「来源够硬」。**
> 所以权威单源论文（Nature/Science 新发，真值 0.90+）**放待观察区，不放核心区** ——
> **单源就是单源，Nature 也不例外。**
> 待观察区不是降级，它是本 skill 最有价值的部分之一：**刚出来、还没人跟进的东西**。


### 3c · 交叉核对

| 情形 | 判定 | 标记 |
|---|---|---|
| 社会面与权威面**都出现**，事实一致 | **强证据** | 🟢 双路确认 |
| 权威面有，社会面无 | 可信但未传播 | 🔵 仅权威 |
| 社会面有，权威面无 | **待验证** —— 可能只是圈内热 | 🟡 仅社会 |
| 两路**互相矛盾** | **必须显式列出矛盾**，不许挑一个 | 🔴 冲突 |
| 只有热榜有 | 大概率噪声 | ⚪ 仅热度 |
| 只有官方自述 | **不算独立验证** | 🟠 自述未独立 |

**质量门**：
- 每条核心候选**都要有三要素结果（含两个权重分）+ 交叉标记**，缺一个不许进阶段 4。
- 🔴 冲突项**必须保留到最终输出**，不许悄悄删掉或二选一。
- 官方自述**不能自己证明自己**。
- **待观察区不许整批丢弃** —— 它是这个 skill 最有价值的部分之一：
  权威面新发的论文天然是"单源"（还没人转载），一丢就只剩已经传开的旧闻。

## 阶段 4 · 精华萃取

**输入**：验证表
**动作**：过滤 → 按事件合并 → **文字编排** → **一致性核对** → 取 3–8 条
**输出**：精华清单（**动态 3–8 条，最低可为 0**），每条保底字段：
`claim / 来源+日期+URL / 三要素 / 交叉标记 / 为什么重要 / 局限 / 一致性核对结果`

### 4a · 过滤

按 `quality-bar.md` 的判据过。**条数靠合并同类项压下来，不许靠删掉不利条目。**

**脚本已做的初筛（信号，不是删除）**：

- `promotional_signal: true` → 真值分 **−0.25**。判据：直达/购买/优惠券/到手价/首发价/预约/开售/京东/天猫，或"价格 + 型号"同现，或 OpenAI News 的客户案例。
  **理由**：详情密度高 ≠ 编辑核验。实测 36氪/IT之家的产品导购靠价格与型号刷满 `evidence_form`，被判 `first-hand-report` 0.78 过闸。
  **但这是信号不是判决** —— 模型仍看得到，可以推翻。
- `degraded_streams` 非空 → 该路数据不完整，**「本次覆盖」必须写明**。
- `archive_truncated` 非空 → 大归档源只取了最新 150 条。

### 4b · 按事件合并

同一事件 → 一条，出处列多个。判重按**事件**不按标题字面。
**★条数靠合并同类项压下来，【不许靠删掉不利条目】。**
**★没有一条通过判据时，如实说「这段时间没有够格的内容」，不要凑数。**

### 4c · 条数：动态 3–8 条（不再固定 5 条）

| 类 | 区间 | 依据 |
|---|---|---|
| 通用 | **3–8 条** | 合格多就多放，少就少放，**最低可以是 0 条** |
| `science` | **最多 8 条** | 实测 science 域闸门后存活 61 条，硬压到 5 条丢掉太多合格内容 |

**★禁止凑数**：合格不足时**如实说明**，不许降级把不够格的塞进来。
**★上限的意义**：逼着做取舍，不是逼着删掉好东西。


**目标：更容易读，同时一个字的主体信息都不丢。**

#### 必须做

| 做 | 说明 |
|---|---|
| **换成自己的话** | 用陈述句重写，不是把原文剪贴过来 |
| **先给结论再给依据** | 读者第一句就知道发生了什么 |
| **长句拆短** | 一句一个事实，不堆从句 |
| **术语展开一次** | 缩写首次出现给全称，之后可用缩写 |
| **按重要性排序** | 重要的先说，不按原文段落顺序 |

#### 绝对不许做

| 不许 | 为什么 |
|---|---|
| **增删数字** | 3.2% 就是 3.2%，不许四舍五入、不许换算 |
| **动因果** | 「A 与 B 相关」不许写成「A 导致 B」 |
| **丢限定条件** | 「在 X 条件下」「仅适用于 Y」必须留 —— 删了就是夸大 |
| **加原文没有的** | 不补背景、不补推测、不补"业内人士认为" |
| **把预印本写成已发表** | 措辞必须保持 `evidence_type` 的原样 |
| **情绪化改写** | 不许加"震撼""重磅""颠覆"这类原文没有的评价 |

#### 一致性核对（编排后必做）

把编排后的 5 条**逐条对回原文**，检查一件具体的事：

> **每一个数字、日期、人名、机构名、限定条件，能不能在原材料里逐字找到出处？**

找不到出处的 —— **要么改回原文措辞，要么删掉这句话**。
这一步是防止"改写过程中把事实改歪"，**编排越流畅，这个风险越高**。

输出时附一行自检：`一致性核对：N/N 通过` 或 `第 N 条已修正：<原措辞> → <改写措辞>`。

**质量门**：
- 条数 **动态 3–8 条**（`science` 可到 8），**最低可以是 0 条**。
- 存疑项**不是删掉，而是降级**到「存疑」区 —— 用户需要知道它存在。
- 没有一条通过判据时，**如实说「这段时间没有够格的内容」**，不要凑数。
- **一致性核对必须做**，不做不许进阶段 5。

## 阶段 5 · 回看（对抗 lost-in-the-middle + 防跑偏）

**为什么有这一步**：长上下文里**中间部分的注意力显著低于首尾**。
本管线尤其危险：三份 JSON 是分批读进来的，
**第一个读进来的那份，到做结论时已经在上下文中间了**，最容易被忽略。

**回看 = 回看已有资料，不是重新检索。** 但**第一步不是补漏，是先校验有没有跑偏。**

### 5a · 先回看用户需求，算关联度

从用户原话里抽出 **3–8 个意图关键词**（能证明"萃取结果确实在回答这个问题"的词），然后量：

```
关联度 = 被萃取结果覆盖的关键词权重 / 用户关键词总权重
```

- **数字和专有名词权重 ×2** —— 丢掉你点名要的数字，比丢掉一个话题词严重得多
- **方向性，不是对称相似度**。分母永远是**你的关键词**，不是双方的并集

> **为什么不能用对称相似度**（实测教训）：你问「AI 安全」，萃取结果跑偏成一堆通用 AI 能力论文 ——
> 双方都有 "AI / 模型 / 训练"，对称相似度**轻松过 0.6**，但萃取实际上完全跑偏了。
> 只有方向性的覆盖率才抓得住这种偏移。

**阈值 0.6**（实测校准过，见下）。

#### 必须量的是「萃取后那 5 条」，不是抓来的全池

**这是实测出来的关键**：拿全池去量，闸门形同虚设 ——
73 条通用 AI 论文里总有一条顺带提过"风险"，于是关键词 `{安全, 对齐, 风险}` 拿到 **1.0**，闸门不响。

所以量的是**你准备发布的那 5 条**。工具：

```bash
# 把萃取结果存成 JSON（entries 列表），然后复检
python scripts/fetch_feeds.py --check-json "$env:TEMP\extracted.json" \
    --keywords 安全 --keywords 对齐 --keywords 风险
```

实测三组对照（阈值 0.6）：

| 萃取结果 | 关键词 | 覆盖 | 判定 |
|---|---|---|---|
| agent / reasoning / benchmark 三篇（贴题） | agent, reasoning, benchmark | **1.0** | 过 |
| 通用 AI 论文三篇（跑偏） | agent, reasoning, benchmark | **0.0** | 触发 |
| 通用 AI 论文三篇（跑偏） | 安全, 对齐, 风险 | **0.0** | 触发 |

### 5b · 关联度 < 0.6 → 二次搜寻（强制）

**不许直接出结论。** 按顺序做：

1. **诊断为什么偏**：是关键词抽错了，还是检索角度不对，还是源里根本没有这个内容？
2. **换角度重搜**：换关键词、换源、放宽时间窗（`--days 7`）、换类的边界。
   —— 注意：如果一个关键词在三路里**一条都匹配不到**，先怀疑**是不是这个领域近期真没有**，
   而不是无限重搜。
3. **重跑权重复核**：新拿到的条目**必须重新过一遍 0.6 闸门和三分区**，不能沿用旧分。
4. **重算关联度**，最高**两轮**。两轮后仍 < 0.6 → **如实报告「本类近期没有用户要的内容」**，
   并列出试过哪些检索角度。**这比硬凑 5 条强。**

### 5c · 然后再做常规回看

四件事，**必须显式写出**（心里过一遍不算）：

1. **逐路复述**：社会面 / 权威面 / 热榜，各用一句话说它说了什么。
   说不出某一句话 → 那一路被漏读了，**回去读**。
2. **点名最早读进来的 3 条**：它们在结论里出现了吗？
   没出现是**因为不重要**，还是**被忘了**？（必须分清）
3. **找回被丢掉的**：阶段 4 过滤掉的里面，有没有其实够格的？
4. **复核三要素**：有没有哪条的「新」或权重分是草率下的？

**输出**（固定格式）：

```
回看记录
  关联度      : <覆盖率> / 0.6  → <过 / 触发二次搜寻（第N轮）>
  漏读补回    : <条目，或「无」>
  误删恢复    : <条目，或「无」>
  权重复核    : <二次搜寻后重算的结果，或「未触发」>
  权重复核    : <二次搜寻后重算的结果，或「未触发」>
  仍存疑      : <条目>
```

**质量门**：
- **关联度必须先算**，且必须是对**萃取结果**算的。
- < 0.6 时**必须走二次搜寻 + 权重复核**，不许跳过。
- 五个字段**都要有内容或明确的「无」**。
- 写了「无」但明显有漏读的，这一步就是走过场 —— **这是整条管线最容易被敷衍的一步**。

## 阶段 6 · 主体结论 + 横向结论

| | 主体结论 | 横向结论 |
|---|---|---|
| **回答什么** | 这个主题**本身**发生了什么变化 | 这些变化**之间**有什么共同模式 |
| **视野** | 纵向 —— 就事论事 | 横向 —— 跨条目、跨领域 |
| **例子** | 「某模型在 X 基准上从 A 提到 B」 | 「本期三条进展都是靠降成本而非提能力取胜」 |
| **能不能只有一条** | 能 | **不能** —— 看不到模式就**明说看不到** |

**横向结论的诚实要求**：从 5 条新闻里「总结趋势」极容易变成编故事。
**模式不成立就写「本期未观察到明确的横向模式」** —— 比编一个漂亮的趋势诚实得多。

**输出**：两组结论，每条都指向具体条目（不许有无出处支撑的结论）。

## 阶段 7 · 对照校验（**强制闸门，不是可选环节**）

> ⚠️ **校验不通过，禁止进入阶段 8。**
> 实测：这个阶段的贡献分只有 8.3%，因为它此前只是"建议做一遍"，
> **淘汰率恒为 0** —— 等于没有。现在它是闸门。

### 7a · 脚本能自动校验的（先做这两条，别用眼睛看）

| # | 自动校验 | 规则 |
|---|---|---|
| ① | **横向结论引用的条目，是否都在主体结论里** | 横向结论里出现主体结论没有的条目 → 该条要么补进主体，要么它其实是主体内容 |
| ② | **主体结论的每一条，是否都被某个结论覆盖** | 有主体条目没被任何结论引用 → 它是噪声（删）或漏了结论（补） |

用 `event_id` 比对，不用标题字面 —— 同一事件的两种措辞会得到不同标题但相同 id。

### 7b · 只有模型能判的

1. 横向结论**有没有足够支撑**？（**≥3 条**条目共同支持才成立，见阶段 6）
2. 两组结论**互相矛盾**吗？矛盾说明有一边推理错了 → **必须解决，不许并列摆着**。
3. 结论**有没有超出证据**？逐条问：「原文真的支持这句话吗？」

### 7c · 修正记录（统一格式，强制留痕）

```
原结论   : <原话>
修正为   : <改后的话>
修正原因 : <超出证据 / 无支撑 / 与另一结论矛盾 / 引用条目不存在>
```

**★校验不通过的结论必须删除或修正，不能保留。**
**★修正记录为空也要写「无修正」，不许省略这一节。**

**输出**：对照校验报告 —— 校验了什么、修正了哪几项、通过率。

## 阶段 8 · 总结论 → 只输出到聊天

> ⚠️ **不落文件、不留缓存。**
> 用户明确要求：**「我在聊天里聊完就算结束，因为我是不会看第二遍的，
> 所以你没必要留文件和缓存。」**
>
> 脚本 `--out` 写到 `$env:TEMP` 的是**抓取管线的中间产物**，可以留；
> **最终报告不写盘、不建产出目录、不调 `present`。** 直接在回复里给完整报告。

**总结论要做什么**：把两个结论收成一句**对用户有用**的话 ——
不是复述，而是回答「**所以我该注意什么**」。

**模板**：

```markdown
# <主题> 情报研判 · <日期范围>

**分类**：社会 / 科学 / AI（三选一）· **参数**：近<N>天 · <条数>条 · 三路全开
**覆盖**：已扫 <X> 源 / 失败 <Y> 源

## 总结论
<2–4 句。真正的变化 + 对用户意味着什么。>
**置信度**：高 / 中 / 低 —— <为什么>

## 主体结论
1. <变化> 〔🟢双路确认｜来源·日期·链接〕
2. …

## 横向结论
<跨条目的共同模式；看不到就写「本期未观察到明确的横向模式」>

## 冲突与存疑
- 🔴 <矛盾项：两路分别怎么说，为什么没定论>
- 🟡 <仅社会面，未获权威确认>
- 🟠 <官方自述，未经独立验证>

## 回看记录
漏读补回 / 误删恢复 / 权重复核 / 仍存疑

## 本次覆盖

- 未覆盖：<本管线看不到的东西>
```

## 三条贯穿全程的红线

1. **子代理只交素材，不交结论。** 让子代理下结论，阶段 3 就没东西可验了。
2. **每条核心内容都要能回答「哪一路来的、三要素如何、验证到什么程度」。** 答不上就是没验证。
3. **「本次覆盖」不许省。** 用户必须知道你没看到什么，
   否则他会以为这份简报是全景 —— 而任何一份都是抽样。
