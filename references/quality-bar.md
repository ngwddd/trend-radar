# 价值判据 · 什么算"高价值"，什么不算

> 这份文件是这份简报**唯一真正值钱的部分**。抓取谁都会，判断什么值得报才是能力。
> 判据要**可执行** —— 能对着一条标题直接判断"过 / 不过"。

---

## 〇、可信度权重（0.6 闸门）—— 这是硬判据，不是感觉

三要素里的 **真实** 和 **传播报道** 不打主观分，**用权重算**。规则写在
`scripts/fetch_feeds.py` 的 `SOURCE_WEIGHT` / `EVIDENCE_WEIGHT` 里，**同一条输入永远得到同一个分数**
（不这样，0.6 这条闸门就没法审计）。

### 依据（不是自己发明的标准）

两套公认的信息评估框架：

- **SIFT**（Caulfield）：Stop · Investigate the source · Find better coverage ·
  **Trace claims to the original context**。
  「回溯一手来源」这一条**就是「真实」在测的东西**。
- **CRAAP**（Meriam Library）：Currency · Relevance · **Authority** · **Accuracy** · Purpose。
  **Authority + Accuracy** 决定下表的源基础权重。

### 真实 = `0.4 × 源权重 + 0.6 × 证据层级`（+0.12 若获独立确认，上限 1.0）

**为什么权威源封顶 0.90 而不是 1.0**：同行评审也会错。留出余量，就没有任何东西能拿到
"完全已验证"，0.6 这条线才有区分度。

**源权重**（按编辑/核验流程的严格程度）：

| 源 | 权重 | 理由 |
|---|---|---|
| Nature / Science / NEJM / Lancet / Cell | 0.90 | 同行评审，顶刊 |
| Nature Medicine / Nature Biotechnology | 0.88 / 0.90 | 同上，子刊 |
| Science Advances / PNAS | 0.86 | 同行评审 |
| OpenAI 官方 | 0.85 | 一手，**但自我利益相关** |
| MIT Tech Review | 0.78 | 有编辑与事实核查 |
| IEEE Spectrum | 0.76 | 同上，偏行业 |
| Ars Technica | 0.72 | 报道较扎实，仍是二手 |
| arXiv | 0.62 | **预印本：有筛查，无同行评审** |
| bioRxiv | 0.60 | 同上 |
| Phys.org | 0.62 | 聚合，常把预印本写成"研究显示" |
| medRxiv | 0.58 | 临床预印本，最弱的一手层级 |
| ScienceDaily | 0.58 | 二手科普，标题夸张 |
| IT之家 | 0.52 | 快，编辑轻 |
| 36氪 | 0.48 | 掺软文与融资 PR |
| Hacker News | 0.45 | 社区投票，无核验 |
| Reddit | 0.40 | 同上 |
| 百度热搜 / 头条热榜 / Google Trends | 0.35 | 点击量，**不是可信度信号** |

**证据层级**：`peer-reviewed 0.92` ｜ `official 0.84` ｜ `dataset 0.78` ｜
`secondary 0.55` ｜ `preprint 0.55` ｜ `rumor 0.25`

**实测结果**（0.6 线）：

```
过  0.91  同行评审（Nature / Science / NEJM）
过  0.90  PNAS
过  0.84  官方公告（OpenAI）
过  0.64  专业媒体二手（Tech Review）
过  0.62  Ars Technica
—— 0.6 线 ——
   0.58  arXiv 预印本 · Phys.org
   0.57  bioRxiv
   0.56  medRxiv · ScienceDaily
   0.54  IT之家
   0.51  Hacker News
   0.33  头条热榜（作正文引用时）
   0.29  百度热搜 / Google Trends
```

**注意 0.6 线正好落在「预印本」和「专业媒体」之间** —— 这不是巧合，是刻意校准的：
**未经同行评审的预印本，不能单独作为事实陈述的依据。**

### 传播报道 = 按**独立来源数**（不是转载次数）

| 独立来源数 | 得分 | 含义 |
|---|---|---|
| 1 | 0.30 | 独家，**未获佐证** |
| 2 | 0.60 | 独立跟报，**刚好过线** |
| 3 | 0.72 | 稳固 |
| 4 | 0.80 | 广泛 |
| 5+ | 0.88 | 极广 |

**「独立」的判定是硬规则，不是数条目**：

- **同一来源的不同入口只算一个**。`hn-frontpage` 与 `hnrss` 是同一个站；
  `arxiv-ai` 与 `arxiv-rss-ai` 是同一个 arXiv。
  （**这是实测出来最危险的一类错**：不合并的话，一条 HN 帖子会被算成"2 个独立来源"，
  源权重只有 0.45 的社区源**反而比 Nature 更容易过闸**。）
- **热榜上的出现不算独立佐证**，只能给传播分加 0.08。
  否则一个人名就能靠热搜过闸。
- 去重按**事件**（标题相似度）不按标题字面 —— 不同媒体报同一件事，标题差很远。

### 闸门怎么用

| 情况 | 处置 |
|---|---|
| 真实 ≥ 0.6 **且** 传播 ≥ 0.6 | 进**核心区** |
| 真实 ≥ 0.6，传播 < 0.6 | **待观察区** —— 可核查但还没传开，**不是丢弃** |
| 传播 ≥ 0.6，真实 < 0.6 | **存疑区** —— 传得广但不可信，必须标明 |
| 两项都 < 0.6 | 丢弃 |

## 〇·二、社会域走**另一套核对系统**（问题4 修复）

**实测事实**：`--domain social --class authority` **返回 0 个源**。
社会域**根本没有权威层级** —— 所以阶段 3c 的「权威面 × 社会面交叉核对」在这个域里
**物理上做不到**。

早期版本的处理是让每条社会内容因为「缺少一个不存在的流」而失败。
现在社会域改走**自己的核对系统**：

```
真实 = 0.30 × 平台可信度 + 0.70 × 证据形式     ← 与默认路径权重相反
传播 = 转载曲线（2 个独立来源 = 0.60，与默认路径同义）+ 0.30 热度加成
```

### 为什么权重是反的

默认路径给源层级 0.4 权重，因为期刊的 ISSN 确实说明可靠性。
**社会域里没有这种层级** —— 按定义它全是二手报道。
区分社会报道好坏的是**证据的形式**（官方通报 vs 无出处转述），不是报头。

### 平台可信度（`PLATFORM_WEIGHT`）

| 平台 | 权重 |
|---|---|
| 政府/官方通报 | 0.92 |
| 央视 / 新华社 | 0.88 |
| 澎湃 / 人民网 | 0.78 |
| 光明网 / 央广 / 中国日报 / 第一财经 | 0.74–0.76 |
| 证券时报 / 新京报 | 0.72 |
| 财新 | 0.80 |
| 36氪 | 0.48 |
| IT之家 / Ars Technica | 0.52 / 0.72 |
| 头条 / 百度 / 微博 | 0.35 |
| **未知媒体** | **0.40 —— 刻意压在闸门下**，不认识的报头不能靠"存在"过闸 |

### 证据形式（`SOCIAL_EVIDENCE_FORM`）—— 这是主权重

| 形式 | 权重 | 判据（**实测，不是声明的**） |
|---|---|---|
| `official-notice` | 0.92 | 官方通报/公告/法规原文 |
| `first-hand-report` | 0.78 | 具体细节得分 ≥ 8（数量/机构/日期/地点） |
| `named-entity` | 0.68 | 得分 ≥ 4 |
| `secondary-report` | 0.52 | 得分 ≥ 1 |
| `unattributed` | 0.30 | 得分 0 —— 无主体、无数字、无时间 |
| `rumor` | 0.25 | |

**具体性是可测量的**：数量词（含 `N`/`W`/`kW` 等国际单位）、具名机构
（局/部/院/公司/集团…）、日期、地名，各计分。
**这比"看报头"更接近"这条可不可信"。**

> ⚠️ **已知限制（明说而非隐藏）**：`in_trend` 要求同一事件**同时**出现在社会池和热度样本里。
> 当前架构下两者是**分开调用的**，所以热度加成**实际不会触发**。
> 保留它是为了以后把两个流接起来时不用重新评分 —— **但今天不要指望热度加成生效**。

**实测效果**（同一批真实条目）：

```
尊界V800 制动踏板断裂    36氪 first-hand-report  truth=0.66  独立3家 → ★双达标
居民医保不涨价           第一财经 named-entity    truth=0.70  独立2家 → ★双达标
多地暂停夜间门诊         澎湃 first-hand-report  truth=0.78  独立1家 → 待观察
新华医院汞超标患儿       澎湃 named-entity       truth=0.72  独立1家 → 待观察
拉萨强迫购物            人民网 secondary-report truth=0.62  独立1家 → 待观察
（自造测试假新闻）       未知  unattributed      truth=0.34         → 丢弃
```

### ⚠️ 热度榜在 social 域内必须被压到 0.45

**实测 bug（我自己的设计自相矛盾）**：热度榜源被标了 `domains:["social"]`，
于是社会分支把它们的**光秃标题**按证据形式打了分 ——
「多家医院、卫生院暂停夜间门诊」拿到 **0.65**，一条热搜短语进了核心区。

**这直接违背本文档下面那条规矩**（"热度榜条目默认一条都不进核心区"）。

**修法**：`truth_weight_social` 里对 `class=trend` 的条目**短路返回 0.45**，
标 `evidence_form: "trend-board(unverifiable)"` 与 `trend_capped: true`。

**理由**：热搜只有标题、**没有正文可验证**，它的真值分在构造上就不可能过闸。
修完热度榜全部 `truth=0.45 / comm=0.65–0.90` → **正确落入存疑区**：
"传得广但不可验证"。**没有一条进核心区。**

> 这条规矩和代码不一致过一阵子 —— **文档说不行、代码让它过了**。
> 所以凡是"默认不许进"的规矩，都必须有代码强制，不能只写在文档里。

## 〇·三、补充检索来的条目也要过权重（问题3 修复）

**实测事实**：一次真实运行里**最该报的三条里两条**是 `web_search` 找到的，
不属于任何注册源 —— 于是**整个权重系统对它们失明**。
子代理按硬约束写 `truth_score: null`、`score_source: "not_scored_by_script"`。

**结果：闸门在保护最不值钱的材料。**

修法：`--extra-json` 注入，按平台表打分。

```bash
python scripts/fetch_feeds.py --domain social --class social --days 3 \
    --extra-json "$env:TEMP\supplemental.json" --out "$env:TEMP\r.json"
```

格式（`also_seen_in` 用于声明独立转载）：

```json
[{"title":"…","source":"澎湃新闻","url":"…","date":"2026-10-09",
  "summary":"…","also_seen_in":["网通社","头条热榜"],
  "signal_words":["…"],"elements":{"new":"yes","truth":"partial","comm":"yes"}}]
```

注入的条目 `reconciliation` 标为 `platform-table(external)`、`score_source` 标为
`platform_table` —— **分数从哪来是可追溯的**。

## 〇·四、两种需求类型，两把尺子（问题2 修复）

**实测失败**：需求「给我社会和 AI 的信息」**没有意图关键词** —— 它是**分类**。
旧版关联度给它算了 **1.0**（或 0.0），**分不出跑偏没跑偏**。
**一个静默放过一切的闸门比没有闸门更糟，因为报告仍然声称检查过。**

修法不是"更好的关键词抽取"（分类需求真的没有关键词），而是**识别需求类型，量对的东西**：

| 需求类型 | 判据 | 度量 |
|---|---|---|
| **关键词型** | 「超导 LK-99 室温」 | 方向性关键词覆盖（不变） |
| **分类型** | 「给我社会和 AI 的信息」 | **域内占比**：萃取结果有多少落在你指定的类里 |

分类型下关键词覆盖**降级为"仅供参考、不参与判定"**并原样记录。
原因：「给我社会和AI的信息」被切成 `['给我社会和', '的信息']` ——
**中文没空格，抽出来是整句，匹配不到任何东西，会把正确的 1.0 拉到 0.0。**

> ⚠️ **分类器的限制，明说而非隐藏**：`DOMAIN_TOKENS` 是**关键词表**，不是分类模型。
> 需求措辞不同就可能判错类型。防线是：**只有需求真的点名了类别才按分类型处理**，
> 否则一律走关键词路径。

**「新」不打权重分** —— 新出现的东西本来就没有转载，
用同一把尺子量它，会**系统性地把最新的内容全部筛掉**。
`新` 由模型判断，写成 `yes / no / partial`。

### ⚠️ 权重最大的局限：同行评审 ≠ 事实正确

**这是实测出来的、必须写明的边界。**

权重表编码的是「这个来源的编辑与核验流程有多严」，**不是「这个结论对不对」**。
所以：

> **一篇被撤稿的 Science 论文，在旧版权重下拿到 0.912 —— 全测试集最高分。**

历史案例实测（三篇"当时共识是错的"的新闻）：

| 案例 | 当时的说法 | 事后真相 | 旧版真值分 |
|---|---|---|---|
| 砷基生命（2010） | NASA + Science：细菌用砷替代磷 | **无法复现，已撤稿** | **0.912** ← 最高 |
| LK-99（2023） | arXiv 预印本：室温常压超导 | 复现全失败，杂质假象 | 0.578 |
| 超光速中微子（2011） | OPERA：中微子快于光速 | 光纤接头松动，测量误差 | 0.578 |

**光靠调权重修不了这个** —— 这是"用可信度代理真值"的固有天花板。

#### 已加的补救：撤稿记录覆盖

Crossref 的 `update-to` 字段带**撤稿 / 关注声明 / 更正**记录
（来源标注 `retraction-watch` 与 `publisher`）。脚本现在会读它，并**短路整个评分**：

| 记录类型 | 真值分处置 | 结果 |
|---|---|---|
| **撤稿** Retraction / Withdrawal | **强制 0.05** | 低于所有闸门 → 压入存疑区，标注「★ 已被撤稿，不得作为事实依据」 |
| **关注声明** Expression of Concern | 上限 0.45 | 存疑区 |
| **更正** Correction / Erratum / Addendum | 上限 0.60 | 勉强过线，**必须标注已被更正** |

**撤稿记录优先级高于一切** —— 包括佐证加成。一篇撤稿论文无论被多少家转载，都是 0.05。

**剩余边界（必须诚实说明）**：

- 这个补救**只在撤稿记录存在时生效**。一项**从未被撤稿、但从未被复现**的结论，
  权重给不出任何警告。LK-99 和 OPERA 都属于这种 —— 它们没被撤稿，只是**没人能复现**。
- 所以**引用任何单篇研究时，措辞必须保持"该研究报告称…"，不是"研究表明…"**。
- **真正防住这类错的是交叉核对（阶段 3c）和待观察区，不是权重。** 权重只管来源，不管真值。

> ⚠️ **真实与传播必须分开算、分别标记。**
> 混成一个分就会掩盖最该被看见的情况：
> 「很可信但没人报」（可能是重要的冷门发现）
> 和「传得很广但不可信」（可能是谣言）。
> 这两者的处置完全不同，合成一个数字就分不出来了。

## 一、通用四条（全部满足才算核心条目）

1. **新事实**：此前没有公开过。不是观点、不是评论、不是预测。
2. **有具体内容**：说得出数字、机制、范围、时间。反面例子：「取得重大突破」「引发广泛关注」。
3. **可核查**：有论文 / 代码 / 数据集 / 官方公告 / 原文链接。
4. **影响可描述**：能一句话说出「这会改变谁做什么」。说不出，就是没影响。

**四条全中 → 核心进展区。中 2–3 条 → 值得留意区。中 0–1 条 → 丢掉，不要为了凑数留下。**

## 二、通用五类噪声（见到直接丢）

| 类型 | 特征 | 为什么丢 |
|---|---|---|
| **盘点/榜单** | 「2026 年十大趋势」「本周必读」 | 没有时效价值，且多数是拼凑 |
| **例行更新** | 模型小版本号、例行榜单刷新 | 不是变化，是噪声 |
| **转载无源** | 多平台同一句话，找不到原始出处 | 无法核查 |
| **观点文** | 只有作者判断，没有新信息 | 不是事实 |
| **融资 PR** | 金额漂亮但无技术/产品细节 | 除非有可验证的产品或数据，否则不进核心区 |

**特别警惕「标题党复述」**：一条新闻被 20 家媒体转，但原始出处只有一个且语焉不详。
这种**降级到存疑区**，并写明为什么存疑。

## 二·五、热度榜专条（阶段 2 路 C）

热度榜（`class=trend`）**默认一条都不进核心区**，除非满足下面这个额外条件：

> **必须能在 social 或 authority 流里回溯到一手来源。**

满足 → 它只是"已在别处抓到的东西，被证明已破圈"，用 `热度确认` 标记附在对应条目上。
不满足 → 它是噪声，**丢掉，不要因为它热就留下**。

实测证据（2026-10-10 同一时刻）：

| 榜单 | 当时第 1 名 | 该不该进核心区 |
|---|---|---|
| 百度热搜 | 宋佳集齐三大奖 | ❌ |
| 头条热榜 | WTT 中国大满贯女单四强 | ❌ |
| Google Trends US | rhyne howard（人名） | ❌ |

**热榜只有两个合法用途**：

1. **校准传播度** —— 某条在 AI 圈内热，但**热榜上也有** → 它破圈了，权重上调。
2. **发现遗漏** —— 热榜上很高但两路都没抓到 → **必须显式判断**：
   是噪声（娱乐八卦），还是真遗漏？**说清是哪种，不许含糊过去。**

> 这条规矩存在的理由：热度衡量的是**点击**，价值衡量的是**变化**。
> 两者经常反向 —— 最有价值的进展通常没多少人搜。

## 三、三大类的合格线

权重（第〇节）管**可信不可信**；本节管**值不值得报**。两者都要过。

### 社会（`social`）

- ✅ **合格**：影响多数人的政策 / 法规 / 价格 / 事故；有具体数字或机制的公共事件；可核查的官方表态
- ⚠️ **看情况**：行业内部变动；地方性事件（除非有外溢影响）
- ❌ **不合格**：娱乐八卦、明星动态、纯情绪话题、体育赛事结果
  —— **除非用户明确要"热搜"而不是"高价值"**

### 科学进步（`science`）

- ✅ **合格**：新机制 / 新测量 / 首次观测 / 推翻既有结论；**有可复现方法或数据**
- ⚠️ **看情况**：增量改进、方法学小修；单中心小样本
- ❌ **不合格**：
  - 勘误 / 更正（`Publisher Correction`、`Author Correction`）—— 脚本已按标题正则丢弃
  - **期刊新闻稿**（Nature 的 `d41586-*` 是 news 不是 research article）→
    **必须与研究论文分开标注**，不能并列为"新研究"
- ⚠️ **必标**：预印本（arXiv / bioRxiv / medRxiv）**一律标注且不写"已证实"**

### AI（`ai`）

- ✅ **合格**：新模型/新方法的**可复现评测结果**；训练或推理成本的实质变化；
  开源权重且附基准；有代码的 agent / 工具链进展
- ⚠️ **看情况**：单点 demo、benchmark 刷榜（除非拉开明显差距）、能力宣称但无第三方复现
- ❌ **不合格**：只有宣传视频、只有"震撼"、只有参数规模、例行小版本号

### 三类共同的淘汰线

| 类型 | 为什么丢 |
|---|---|
| **盘点/榜单** | 「2026 年十大趋势」没有时效价值，多为拼凑 |
| **例行更新** | 小版本号、例行榜单刷新 —— 不是变化，是噪声 |
| **转载无源** | 多平台同一句话，找不到原始出处 |
| **纯观点文** | 只有作者判断，没有新信息 |
| **融资 PR** | 金额漂亮但无技术/产品细节 |

**特别警惕「标题党复述」**：一条新闻被 20 家媒体转，但原始出处只有一个且语焉不详。
这种**降级到存疑区**，并写明为什么存疑 —— 注意它的 `comm_score` 会很高（转载多），
但 `truth_score` 低，**两个分必须分开看，这正是分开算的理由**。

## 四、来源可信度分级（影响条目怎么写）

（与第〇节的权重表一致，这里是**写法**层面的对应）

| 级别 | 来源 | 权重 | 写法 |
|---|---|---|---|
| **一手** | 论文原文、官方公告、官方代码库 | 0.84–0.90 | 可作事实陈述 |
| **二手可信** | 专业媒体（Tech Review、IEEE Spectrum、Ars Technica） | 0.72–0.78 | 陈述时标明来源 |
| **预印本** | arXiv / bioRxiv / medRxiv | 0.58–0.62 | **不写"已证实"**，必须标预印本 |
| **二手科普** | Phys.org、ScienceDaily | 0.56–0.62 | **必须回溯一手论文**，它们常把预印本写成"研究显示" |
| **线索级** | HN、Reddit、36氪、IT之家 | 0.40–0.52 | **只当线索**，回溯到一手来源才能进核心区 |
| **热度级** | 百度热搜、头条热榜、Google Trends | 0.35 | **不作内容来源**，只作传播度校准 |
| **不可用** | 找不到出处的转述、AI 内容农场 | — | 丢弃 |

**同一事件横跨多级时，按最高级别写，但必须列出原始链接。**
权重不许因为"多家转了"就上调 —— 一手来源就是一手，转载改变的是**传播分**，不是**真实分**。

## 五、数值与因果的铁律

- **不许换算**：原文写 3.2%，就写 3.2%，不要"约 3%"。
- **不许外推**：论文说"在 X 数据集上提升 12%"，不要写成"性能提升 12%"。
- **不许合并因果**：两件事同时发生 ≠ 有因果关系。
- **不许补全**：摘要没提的限制条件，不要替作者说"可能"。
- **预印本必须标注**且不写"已证实"。
- **保留限定条件**：「在 X 条件下」「仅适用于 Y」砍掉就变成夸大。
- **数字与量词**：含糊量词（"大幅""显著"）要么换成原文数字，要么标「原文未给数」。
- **`signal_words` 里的修饰词要在正文可见** —— 它们是报道者判断的痕迹，不是噪声。
