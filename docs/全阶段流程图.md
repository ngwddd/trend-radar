**核心分工原则**：**体力活交给脚本，判断交给模型。**
脚本负责抓取、时间窗、去重、权重、闸门 —— 确定性的部分；
模型负责价值判断、萃取、编排、结论 —— 需要理解的部分。

**红线**：子代理**只交素材，不交结论**。让子代理下结论，阶段 3 就没东西可验了。

### 阶段 1 的已知问题

| # | 问题 | 影响 |
|---|---|---|
| 1 | **`hits = 1` 且没给 `--domain` → 判成关键词型**。说「科学界有什么进展」不给 `--domain`，中文抽词抽出整句，匹配不到东西 → 关联度接近 0 → **误触发二次搜寻** | 中 |
| 2 | **分类判错下游发现不了**。阶段 3 只验内容真不真，**不验分类对不对**。错了会一路污染到最后且无任何环节报错 | 高 |
| 3 | **`--request` 与 `--domain` 冲突时优先级未定义**。代码里 `--domain` 事实上赢（它决定源），但 `request_type` 仍按 request 文本判 | 低 |
| 4 | `ai` 被当停用词滤掉是对的（否则"AI"能替"AI安全"作证），但代价是 AI 类请求的关键词质量更差 | 低 |

# 三条贯穿全程的红线

```
① 子代理只交素材，不交结论。
   → 让子代理下结论，阶段 3 就没东西可验了。

② 每条核心内容都要能回答「哪一路来的、三要素如何、验证到什么程度」。
   → 答不上就是没验证。

③ 「本次覆盖」不许省。
   → 用户必须知道你没看到什么，否则他会以为这份简报是全景 ——
     而任何一份都是抽样。
```

# 八处已知限制（写进代码注释，不是口头承诺）

| # | 限制 | 位置 |
|---|---|---|
| 1 | **同行评审 ≠ 事实正确**。权重编码"编辑流程多严"，不是"结论对不对" | quality-bar.md 第〇节 |
| 2 | 撤稿拦截**只在撤稿记录存在时生效**。从未被撤稿、只是没人复现的**没有任何警告** | 同上 |
| 3 | **热度加成实际不会触发**（`in_trend` 要求两个流同时出现，但两者分开调用） | `comm_weight_social` docstring |
| 4 | `DOMAIN_TOKENS` 是**关键词表不是分类模型** | quality-bar.md 第〇·四节 |
| 5 | 阶段权重里 `gain`/`error_prevented` 是**人工判定**，只能用排序不能用绝对值 | 阶段权重分析\方法说明.md |
| 6 | **付费墙正文读不到**（Science/Cell 实测被挡） | SKILL.md 边界节 |
| 7 | `RE_QUANTITY` 单位不一致（`5278批次` 匹配不到）；`RE_PLACE` 偶有误判 | 阶段 3 已知问题 |
| 8 | `test_retraction.py` **完全不覆盖社会分支** | tests\ |
